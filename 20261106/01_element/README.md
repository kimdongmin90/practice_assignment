# 객체 탐지(Object Detection) Ground Truth 및 OpenCV 시각화 분석

## 1. GT(Ground Truth)에도 confidence(확신도)가 있는가?

**결론부터 말씀드리면, 일반적인 GT 데이터에는 confidence 값이 존재하지 않으며 필요하지도 않습니다.**

* **GT의 정의:** GT는 사람이 직접 이미지 내부의 객체를 확인하고 라벨링한 '실제 정답(True Target)' 데이터입니다. 수학적으로 100% 참(`1.0`)으로 간주되는 기준선입니다.
* **출력 데이터 확인:** 코드 실행 결과에서도 `GT confidence: N/A`(해당 없음)로 출력되는 것처럼, 정답 데이터셋 구성 요소에는 확신도라는 개념을 따로 기록하지 않습니다.
* **비교 (Prediction):** 반면, 인공지능 모델이 추론한 예측(Prediction) 결과에는 모델이 그 정답을 얼마나 확신하는지에 대한 점수(`0.0 ~ 1.0` 사이의 Confidence Score)가 항상 함께 부여됩니다.

---

## 2. 색의 BGR 순서의 의미

코드 내 `cv2.rectangle` 함수에 사용된 색상 인자는 **`(255, 0, 0)`**입니다.

* **OpenCV 표준 규격:** 대중적인 이미지 라이브러리와 달리 OpenCV는 이미지를 처리할 때 RGB가 아닌 **BGR (Blue, Green, Red)** 순서를 표준 배열로 사용합니다.
* **색상 매핑 결과:** 
  * `(255, 0, 0)`은 첫 번째 채널인 **순수한 파란색(Blue)**을 뜻합니다.
  * 만약 초록색 박스를 원한다면 `(0, 255, 0)`, 빨간색 박스를 원한다면 `(0, 0, 255)`로 지정해야 합니다.

---

## 3. xyxy 좌표의 의미

`xyxy`는 컴퓨터 비전 영역에서 사각형 바운딩 박스(Bounding Box)의 영역을 지정하는장 표준적인 좌표계 표현 방식입니다. **사각형의 대각선 두 꼭지점의 위치**를 나타냅니다.

* **`(x1, y1)`:** 사각형의 **좌측 상단(Top-Left)** 꼭지점의 가로(x축), 세로(y축) 픽셀 좌표입니다.
* **`(x2, y2)`:** 사각형의 **우측 하단(Bottom-Right)** 꼭지점의 가로(x축), 세로(y축) 픽셀 좌표입니다.

### 📊 첫 번째 객체 데이터 예시 해석
```text
class: 0 xyxy: 12 18 52 58
```
* 해당 데이터는 전체 크기 `(128, 160)` 해상도의 이미지 안에서, **가로 12번째, 세로 18번째 픽셀** 위치부터 **가로 52번째, 세로 58번째 픽셀**까지 감싸는 영역에 `0번 클래스`에 해당하는 객체가 존재한다는 의미입니다.

본 문서는 제공된 이미지 데이터 규격(`shape: (128, 160, 3)`)과 정규화 결과값을 바탕으로, 객체 탐지(Object Detection) 파이프라인에서 가로(`width`)와 세로(`height`) 기준을 뒤바꿔 정규화(또는 역정규화)할 때 발생하는 구조적 문제점을 규명합니다.

---

## 1. 핵심 요약 (Main Takeaway)
**이미지가 직사각형(가로 $\neq$ 세로)인 경우, 가로세로 기준을 바꾸어 정규화하면 바운딩 박스의 크기뿐만 아니라 종횡비(Aspect Ratio)가 심각하게 왜곡되어 객체의 물리적 형태가 파괴됩니다.** 이로 인해 모델이 잘못된 형태의 박스를 학습하게 되며, 추후 성능 평가 지표인 IoU 및 mAP가 급격히 하락합니다.

---

## 2. 세부 문제점

### 1) 이미지 종횡비(Aspect Ratio) 불일치로 인한 박스 찌그러짐
제공된 이미지의 해상도는 **가로 160 픽셀, 세로 128 픽셀**로 5:4 비율의 직사각형 구조입니다. 
* 정규화된 가로(`width`) 값은 **160**으로 나눠진 값입니다.
* 정규화된 세로(`height`) 값은 **128**로 나눠진 값입니다.

만약 두 기준을 뒤바꿔 가로 비율에 128을 곱하고 세로 비율에 160을 곱하여 픽셀을 복원하면, 본래 크기와 완전히 다른 엉뚱한 직사각형이 그려집니다.

### 2) 실제 데이터 수치 검증 (`basic_train_000.png` - `square`)
출력 데이터의 첫 번째 객체인 `square` 제품군의 정상 복원 결과와 왜곡 결과를 수치적으로 비교해 보면 문제점이 더욱 명확해집니다.

* **정상 복원 (정밀 계산):**
  * 실제 가로 폭: $0.19375 \times 160 = 31\text{ 픽셀}$
  * 실제 세로 높이: $0.2421875 \times 128 = 31\text{ 픽셀}$
  * **결과:** 가로 31, 세로 31의 완벽한 **정사각형(Square)** 객체입니다.

* **가로·세로 기준을 바꾼 오류 복원:**
  * 오류 가로 폭: $0.19375 \times 128 \approx 24.8\text{ 픽셀}$
  * 오류 세로 높이: $0.2421875 \times 160 \approx 38.75\text{ 픽셀}$
  * **결과:** 이름은 정사각형(`square`)인데 실제 시스템이 인지하는 박스는 가로가 좁고 세로로 홀쭉한 **직사각형(25x39)**으로 찌그러집니다.

### 3) 공간 왜곡으로 인한 모델 학습 실패
YOLO와 같은 객체 탐지 모델은 객체의 형태적 특징(가로세로 비율, 경계선)을 학습합니다. 
* 정규화 기준이 꼬이면 같은 `square` 클래스임에도 불구하고 이미지의 회전이나 위치에 따라 매번 다른 비율로 박스가 늘어나거나 줄어들게 됩니다.
* 이는 라벨 데이터 자체에 엄청난 노이즈를 주입하는 꼴이 되어 모델의 수렴(Loss 감소)을 방해하고 탐지 정확도를 극도로 떨어뜨립니다.

## 3. 결론

## 2. `.yaml` 파일과 `.pt` 파일의 차이점

YOLO 프레임워크에서 두 파일은 역할을 철저히 분리하여 모델을 빌드하고 추론하는 데 사용됩니다.

| 항목 | `.yaml` (Configuration File) | `.pt` (PyTorch Weight File) |
| :--- | :--- | :--- |
| **정의** | 텍스트 기반의 **설정/구조 명세서** | 이진 데이터(Binary) 기반의 **신경망 가중치 파일** |
| **성격** | 설계도 (Blueprint) | 실제 건축물 (Physical Building) |
| **내용물** | 모델 레이어 구조, 채널 수, 데이터셋 경로 등 | 학습을 통해 최적화된 뉴럴 네트워크의 **수치 행렬(Weight 데이터)** |
| **용량** | 수 KB 내외 (텍스트 파일이라 매우 가벼움) | 수 MB ~ 수백 MB (수백만 개 파라미터가 압축 저장됨) |
| **가독성** | 메모장으로 열어 사람이 즉시 읽고 수정 가능 | 컴퓨터(PyTorch 연산 엔진)만 해석 가능한 바이너리 형태 |

### 🛠️ 프로젝트 내부에서의 구체적 역할 비교

* **`yolo26n.yaml` (`.yaml` 형식)**
  * 모델의 뼈대를 의미합니다. "0번 레이어는 Conv이고 채널은 몇 개다", "23번 레이어는 Detect 헤드다"와 같이 **신경망의 연결 관계 및 규칙만 적힌 레시피**입니다. 
  * 내부에 실제 '지능(값)'이 들어있지 않기 때문에, 이것만 가지고 로드하면 모델은 무작위 난수 값으로 초기화되어 아무것도 탐지하지 못합니다.

* **`best.pt` 또는 `last.pt` (`.pt` 형식)**
  * `.yaml` 설계도에 따라 생성된 레이어 부포들 사이에 주입되는 **물리적인 세포(뉴런의 연결 강도 스펙)**입니다.
  * 학습을 거듭할수록 이 `.pt` 내부의 부동소수점 매트릭스 수치들이 정교하게 정렬되며, 실제 배포 시스템이나 추론 코드를 실행할 때는 이 파일만 단독으로 불러와서(`YOLO("best.pt")`) 인공지능 탐지 기능을 즉시 수행할 수 있습니다.

 정의: IoU 임계값을 0.50부터 0.95까지 0.05 단위로 쪼갠 총 10개의 임계값($0.50, 0.55, 0.60, \dots, 0.95$) 각각에서 mAP를 계산한 뒤, 이 점수들의 **산술 평균**을 낸 최종 지표입니다.
 특징: IoU 0.90이나 0.95와 같은 가혹한 임계값 구간에서는 예측 상자가 정답 영역과 거의 90%~95% 이상 한 치의 오차도 없이 완벽하게 포개어져야만 정답으로 인정합니다. 이 엄격한 고난도 구간들에서는 모델의 Precision 점수가 극단적으로 떨어지기 때문에 전체 평균을 깎아 먹게 됩니다.

1) 모의고사(Val)와 수능 시험(Test)의 원자적 분리
 Validation (Val) 데이터셋: 학습 과정 중에 모델의 현재 성능을 체크하고 신뢰도 임계값(`conf=0.25`), NMS 스케일, 혹은 가중치 세트 선택(`best.pt` 선정) 등의 **하이퍼파라미터를 미세 조정(Tuning)하기 위해 사용하는 데이터셋**입니다.
 Test 데이터셋: 모델의 모든 설계, 에포크 최적화, 임계값 튜닝이 완벽히 끝나고 배포(Release)되기 직전, **"단 한 번만" 채점하여 일반화 성능을 객관적으로 증명하는 용도**입니다.

 2) 데이터 누수(Data Leakage) 차단 및 사기 점수 방지
 만약 임계값을 조절하거나 오답 분석(Grad-CAM 등)을 진행하는 현재 파이프라인 개발 단계에서 미리 테스트셋(`test`)을 열어보고 코드를 수정하게 되면, 모델과 개발자가 테스트셋의 특성에 수동으로 과적합(Overfitting)되는 **데이터 누수 현상**이 발생합니다.

1. 고유 ID의 개수(Total ID Count)와 ID 스위치(ID Switch)의 차이

 결론부터 말씀드리면, 고유 ID의 개수와 ID 스위치(ID Switch)는 완전히 다른 개념이며 일치하지 않습니다.

1) 고유 ID의 개수 (Total ID Count)
정의: 비디오 스트림 전체 시퀀스 동안 모델과 추적기가 탐지하여 부여한 **고유한 객체 식별 번호(`track_id`)의 총합**입니다.
해석: 예를 들어 화면에 사각형 1개, 원 1개가 처음부터 끝까지 움직였다면 이상적인 고유 ID의 개수는 `2`개가 되어야 합니다.

2) ID 스위치 (ID Switch, IDSW)
정의: 특정 객체가 이동하는 과정에서 폐쇄(Occlusion, 데이터 겹침), 급격한 조명 변화, 혹은 탐지 실패로 인해 **추적기가 동일 객체를 놓쳤다가 다시 찾았을 때, 기존 ID가 아닌 새로운 ID를 잘못 부여하는 오류 현상**입니다.
해석: 원래 `ID: 1`번이었던 사각형 객체가 원 객체 뒤로 가려졌다가 나오면서 `ID: 3`번으로 뒤바뀌었다면, 실제 객체는 여전히 1개(사각형)이지만 **ID Switch가 1회 발생**한 것입니다. 이 경우 시스템에 기록되는 전체 고유 ID의 개수는 불필요하게 `3`개로 늘어나 실전 실력보다 모수가 부풀려지게 됩니다.

---

2. 새로운 영상(새 스트림)에 이전 Tracker 상태를 붙여 실행(`persist=True`)할 때의 문제점

YOLO의 `track()` 메서드에서 `persist=True` 옵션은 동일 파일 내 프레임 연속성을 보장하는 데 필수적입니다. 하지만 **서로 다른 완전한 별개의 새 영상(New Video)을 시작하면서 이전 영상의 추적 상태(Kalman Filter 가중치 및 메모리 뱅크)를 그대로 이어붙이면** 다음과 같은 심각한 아키텍처적 결함이 발생합니다.

1) 무결성이 파괴된 궤적 연결 오류 (치명적인 ID 스위치 폭증)
 이전 동영상 마지막 프레임에서 화면 우측 하단에 위치했던 `ID: 5`번 객체의 속도와 위치 정보가 추적기 메모리에 남아있게 됩니다.
 이 상태에서 완전히 새로운 별개의 영상이 시작되면, 새 영상의 1번째 프레임 좌측 상단에 등장한 완전히 다른 객체에게 이전의 `ID: 5`번을 덮어씌워 버리거나 칼만 필터 예측 좌표가 급격하게 요동치는 오작동이 일어납니다.

2) 칼만 필터(Kalman Filter)의 상태 예측 그래프 붕괴
 추적 알고리즘 내부의 가속도 및 위치 예측 엔진은 직전 프레임의 연속성을 전제로 수학적 가중치를 누적합니다.
 영상이 바뀌면서 시각적 맥락(Context)이 단절되었음에도 이전 상태를 강제 주입하면, 시스템은 객체가 비정상적으로 순간이동했다고 인지하여 내부 분산 행렬(Covariance Matrix) 값이 터지게 되며, 결국 궤적 추적 능력을 완전히 상실하게 됩니다.
